# 01-快速上手：10 分钟让机器人动起来

> 面向场景：你手里有一台**优必选 Visbot（小方头）机器人**，官方已经不再维护。你想自己写一个应用，让它**扭头、走路、挥手、做表情**——就像给这台旧设备注入"具身智能"。
>
> 本文假设你会 Android 基础开发（会建工程、会跑 Hello World），带你从零到"机器人听你的"。

---

## 1. 先搞清楚：机器人为什么能被我控制？

这台机器人运行 Android 系统，内部有一个**系统服务（Master 服务）**，所有物理能力（舵机、轮子电机、表情屏、LED 灯、传感器、回充桩）都由它统一管理。官方给开发者用的就是这套"Rosa 平台"：

```
你的应用 ──(Binder IPC)──▶ Master 系统服务 ──▶ 硬件驱动 ──▶ 舵机/轮子/屏幕/灯
```

两条使用路线（本套文档都覆盖）：

| 路线 | 依赖 | 适合场景 |
|------|------|----------|
| **A. 官方 SDK（rosa.jar）** | `tmp/ubt_repo/visbot-sdk/libs/rosa.jar`（已从设备提取并反编译验证） | 绝大多数开发，API 完整 |
| **B. 裸 Binder IPC** | 无任何依赖 | 特殊需求、SDK 无法满足时（见 AI 文档 08） |

> 路线 B 的完整协议已在 `AI指导规范文档/08-Master服务底层IPC协议.md` 中还原，本篇走路线 A。

---

## 2. 硬性前置条件（缺一不可）

1. **设备上有 Master 服务**：Visbot 出厂自带（包名 `com.ubtrobot.systemservice`）。任何刷掉系统的设备无法使用本方案。
2. **APK 必须用系统签名**：Master 服务只接受与系统同 UID 的调用方。清单里必须写 `android:sharedUserId="android.uid.system"`，并且用**平台密钥**签名 APK。
3. **平台密钥已有现成的**：`tmp/ubt_repo/keystore/platform.jks`（这是 AOSP 公开测试签名，恰好与小方头的系统签名一致，**真机已验证可用**）。密码/别名都是 `android`。

> 注意：这套签名只对使用默认 AOSP 签名的设备有效。装到普通手机上是装不上的（UID 冲突），但没关系——你的目标就是这台机器人。

## 3. 最省事的起步方式：直接用现成工程

`tmp/ubt_repo/` 是一个**已经配置好签名、权限、依赖的完整 Android 工程**（真机验证通过：扭头、走路都动过）：

```
tmp/ubt_repo/
├── app/                      # 示例应用（MainActivity 就是控制面板）
├── visbot-sdk/               # SDK 封装模块（内含 rosa.jar + 裸 IPC 实现）
├── keystore/platform.jks     # 系统签名（密码 android）
└── libs/rosa.jar             # 官方 SDK（独立副本）
```

**最快的验证步骤（10 分钟）：**

1. 用 Android Studio 打开 `tmp/ubt_repo/`
2. USB 连接机器人（开启 USB 调试），点 Run
3. 界面出现"✓ Master服务连接成功"后 2 秒，机器人的**头会自动转动**（示例内置了自动测试）
4. 之后点"前进/后退/左转/右转/停止"按钮，机器人会**走起来**

如果第 3 步失败，见第 7 节排障。

## 4. 从零建工程（不想用现成工程时）

### 4.1 依赖 rosa.jar

把 `rosa.jar` 复制到你的工程 `app/libs/`，并在 `build.gradle` 里加：

```groovy
android {
    // 必须用系统签名（见 4.3）
}
dependencies {
    implementation files('libs/rosa.jar')
}
```

### 4.2 AndroidManifest 两处关键配置

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    android:sharedUserId="android.uid.system">   <!-- ① 系统 UID -->

    <uses-permission android:name="com.ubtrobot.permission.ROBOT" />  <!-- ② 机器人权限 -->

    <application ...>
        ...
    </application>
</manifest>
```

### 4.3 系统签名配置

```groovy
android {
    signingConfigs {
        platform {
            storeFile file('keystore/platform.jks')
            storePassword 'android'
            keyAlias 'platform'
            keyPassword 'android'
        }
    }
    buildTypes {
        debug   { signingConfig signingConfigs.platform }   // debug 也签
        release { signingConfig signingConfigs.platform }
    }
}
```

### 4.4 命令行签名（不想改 gradle 时）

```bash
# 先用正常方式打出未签名/普通签名的 APK，然后重新签名：
keytool -importkeystore \
  -srckeystore keystore/platform.p12 -srcstoretype PKCS12 -srcstorepass android \
  -destkeystore platform.jks -deststoretype JKS -deststorepass android
# 用 apksigner 重签：
apksigner sign --ks platform.jks --ks-pass pass:android \
  --key-pass pass:android --out app-signed.apk app-unsigned.apk
```

## 5. 第一段代码：让机器人扭头

```java
import android.app.Application;
import com.ubtrobot.Robot;
import com.ubtrobot.servo.ServoController;
import com.ubtrobot.servo.RotationOption;

public class MyApp extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        // ① 初始化 SDK（Application 里做一次即可）
        Robot.initialize(this);
    }
}
```

```java
// ② 拿到舵机控制器（"servo" 是服务名，固定字符串）
ServoController servo = Robot.globalContext().getSystemService("servo");

// ③ 让头转到 -20°（真机实测 head 舵机安全范围约 [-23, 25]）
servo.rotate(new RotationOption.Builder("head")
        .setAngle(-20f)
        .setSpeed(50)          // 速度 50
        .build())
    .done(v -> Log.i("Robot", "扭头完成"));
```

装上运行，机器人的头就动了。

> `head` 是这台设备**实测确认**的舵机 ID。想枚举全部舵机：`servo.getDeviceList()`（见 AI 文档 02）。

## 6. 第一段代码：让机器人走路 / 挥手 / 做表情

```java
// —— 走路 ——
LocomotionController loco = Robot.globalContext().getSystemService("locomotion");
// 前进，速度 0.3（真机已验证值），持续 2 秒
loco.locomote(new LocomotionOption.Builder()
        .setMovingSpeed(0.3f)
        .setDuration(2000)
        .build());

// —— 挥手 ——
// 挥手 = 手臂舵机（arm_left/arm_right，以 getDeviceList() 实际返回为准）来回摆，
// 用 rotateSerially 串行执行「抬起→放下」×3，不阻塞主线程：
ServoController servo = Robot.globalContext().getSystemService("servo");
List<RotationOption> wave = new ArrayList<>();
for (int i = 0; i < 3; i++) {
    wave.add(new RotationOption.Builder("arm_left").setAngle(-60f).setSpeed(80).build());
    wave.add(new RotationOption.Builder("arm_left").setAngle(20f).setSpeed(80).build());
}
servo.rotateSerially(wave).done(v -> Log.i("Robot", "挥手完成"));

// —— 表情 ——
EmotionController emotion = Robot.globalContext().getSystemService("emotion");
emotion.express(new ExpressingOption.Builder(
        Uri.parse("ubtrobot://emotion/happy"))   // URI 需在设备上枚举（见 AI 文档 05）
        .setSticky(true)
        .build());

// —— 灯光 ——
LightController light = Robot.globalContext().getSystemService("light");
light.turnOn("eye_left", 0xFF00FF00);   // 左眼绿色（灯 ID 以 getDeviceList 为准）
```

## 7. 排障清单（按顺序查）

| 现象 | 原因 | 解决 |
|------|------|------|
| 装不上：`INSTALL_FAILED_SHARED_USER_INCOMPATIBLE` | APK 不是平台签名 | 检查 signingConfig 生效；`apksigner verify` 看证书 SHA256 是否等于 `C8:A2:E9:BC:CF:59:7C:2F:B6:DC:66:BE:E2:93:FC:13:F2:FC:47:EC:77:BC:6B:2B:0D:52:C1:1F:51:19:2A:B8` |
| 装上但连接 Master 失败 | 设备系统服务不在 / 版本不匹配 | `adb shell pm list packages \| grep ubtrobot` 确认 `com.ubtrobot.systemservice` 存在 |
| 调用返回失败 code≠0 | 竞争会话未分配（多应用抢硬件） | 用 `SessionAllocator("servo", ...)` 申请会话（见 AI 文档 08 §6） |
| 舵机不动 | 角度超出机械范围 | head 用 [-23, 25] 实测范围；先 `getDeviceList()` 枚举 ID |
| 动作/表情 URI 无效 | URI 每台设备不同 | 必须在设备上枚举（AI 文档 04/05 给了 4 种途径） |
