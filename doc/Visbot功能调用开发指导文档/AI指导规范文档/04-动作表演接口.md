# 04-动作表演（Motion）接口

> 用途：播放设备内置的**预置动作**（挥手、鞠躬、跳舞、欢迎等成套动作文件）→ 这是实现"挥手/点头/舞蹈"等高层次动作的最简路径，无需逐关节编程。
> 接口源码：`tmp/rosa_decompiled/sources/com/ubtrobot/motion/MotionController.java`

## 获取控制器

```java
import com.ubtrobot.Robot;
import com.ubtrobot.motion.MotionController;
import com.ubtrobot.motion.PerformingOption;

Robot.initialize(context.getApplicationContext());
MotionController motion = Robot.globalContext().getSystemService("motion");
```

## 接口全貌

```java
public interface MotionController {
    ProgressivePromise<Void, PerformingException, PerformingProgress> performAction(PerformingOption option);
    ProgressivePromise<Void, PerformingException, PerformingProgress> performActionSerially(List<PerformingOption> options);
    Posture getPosture();                 // 当前姿态（站立/趴下等）
    boolean isPerformingAction();         // 是否正在表演动作
}
```

## PerformingOption（动作参数）

```java
PerformingOption option = new PerformingOption.Builder(actionUri)
    .setLoops(1)          // 循环次数；负数/0 自动修正为 1
    .setBpm(1.0f)         // 节拍倍速；>0，1.0=原速，2.0=双倍速
    .setStartTime(0)      // 动作文件内偏移起始时间（毫秒）
    .build();
```

Builder 还有复制构造：`new PerformingOption.Builder(existingOption)`。

## 执行预置动作

```java
// 播放动作：actionUri 指向设备动作库中的动作
Uri actionUri = Uri.parse("ubtrobot://action/wave");  // 挥手（URI 需以设备动作库为准）

motion.performAction(new PerformingOption.Builder(actionUri)
        .setLoops(2)      // 挥两次
        .setBpm(1.5f)     // 1.5 倍速
        .build())
    .done(new DoneCallback<Void>() {
        @Override public void onDone(Void v) { Log.i("M", "动作完成"); }
    })
    .fail(new FailCallback<PerformingException>() {
        @Override public void onFail(PerformingException e) {
            Log.e("M", "动作失败 code=" + e.getCode());
        }
    })
    .progress(new ProgressivePromise.ProgressCallback<PerformingProgress>() {
        @Override public void onProgress(PerformingProgress p) {
            // p.getProgress() 0..1
        }
    });
```

## 串行编排（动作序列 = 一段表演）

```java
List<PerformingOption> show = Arrays.asList(
    new PerformingOption.Builder(Uri.parse("ubtrobot://action/wave")).build(),
    new PerformingOption.Builder(Uri.parse("ubtrobot://action/bow")).build(),
    new PerformingOption.Builder(Uri.parse("ubtrobot://action/dance")).setLoops(2).build()
);
motion.performActionSerially(show);
```

## 状态查询

```java
boolean performing = motion.isPerformingAction();
Posture posture = motion.getPosture();   // Posture 对象包含当前姿态描述
```

## 动作 URI 从哪来（关键）

`PerformingOption` 需要动作 URI，但 rosa.jar 的 `MotionController` 接口**没有列出动作清单的方法**。实际获取途径：

1. **设备动作库**：动作文件位于设备系统分区或数据分区（如 `/system/motion/`、`/data/motion/`），可用 adb 枚举：
   ```bash
   adb shell find /system /data /vendor -type d -iname "*motion*" 2>/dev/null
   adb shell find /system /data /vendor -type f \( -iname "*.xml" -o -iname "*.json" \) 2>/dev/null | grep -iE "action|motion|posture" | head -50
   ```

2. **通过 Master 服务直接查询**：动作服务暴露 `/motion/action` 类查询路径（参照 servo 的 `/servo/device-list` 模式），可用 08 的 `MasterConnection.call()` 试：
   ```java
   MasterServiceProxy master = new MasterServiceProxy(context);
   // 尝试常见查询路径
   master.call("/motion/action-list", new HashMap<>());
   master.call("/motion/actions", new HashMap<>());
   ```

3. **抓原厂应用调用**：原厂应用（com.ubtech.visbot）执行动作时 logcat 过滤 Master 日志：
   ```bash
   adb logcat | Select-String -Pattern "motion|action"
   ```

4. **逆向动作资源**：原厂 APK 的 `assets/` 或服务器的动作资源包（Visbot APK 的 assets 中未含动作文件，说明动作库在系统分区或云端）。

## 与舵机/运动的区别（选型指导）

| 需求 | 推荐接口 |
|------|----------|
| 简单挥手、鞠躬、成套舞蹈 | **MotionController**（动作文件一次搞定） |
| 扭头到具体角度、单关节控制 | ServoController（02） |
| 走路、转向 | LocomotionController（03） |
| 动作+表情+灯光的组合演出 | Motion + Emotion + Light 串行编排 |

## 底层服务路径（备查）

```
/motion/perform
```

参数为 Parcelable `PerformingOption`（经 `ParcelableCallAdapter`），见 08。

## 设备端验证建议

由于动作 URI 依赖设备动作库，开发时先写一个"动作枚举器"应用：遍历候选 URI 并逐个 `performAction` 试播，把可用的 URI 记录下来（参照示例工程 MainActivity 的自动测试模式）。
